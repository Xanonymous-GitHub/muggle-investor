# Muggle Investor 階段 4：問問看與 PWA 收尾

狀態：4A（問問看後端）已實作（2026-10-17）。4B（聊天畫面）與 4C（PWA 收尾）尚未開始。

承接 `2026-10-11-muggle-investor-design.md` 的第 4 階段。標示「（使用者已決定）」的是使用者說過或同意的；其餘是我的決定，使用者可以否決。

## 目的與原因

「問問看」讓使用者用自己的話問市場與自己的投資，得到一個「AI 分析師的聲音」：有觀點、有依據、有情境、有具體建議。使用者的目標是讓這個聲音**真的有用**，所以它不只重述資料，還要能預測與建議，並能自己去查新聞、公司關係等本系統沒有的資料。使用者知道這是 AI 的說法並自負風險。

使用者給的例子（只是起點，不是完整範圍）：
- 現在市場發生什麼事？我還會賺錢嗎？
- 市場在跌，我要不要調整手上的投資？
- 這個名詞 xxx 是什麼意思？
- 看看我的投資，你覺得市場在 xxx 天／個月內會 xxx 嗎？

## 目標

- 手機與桌機都能順暢對話，串流顯示，沿用既有外框、主題、入門與專業視角、名詞晶片。
- 回答先給結論，再給依據、情境與信心程度；入門與專業兩種視角的深度與用字不同。
- 能使用工具（內建資料、搜尋、MCP、skills）查證，所有事實與數字可追溯到工具結果或本系統資料，網路來源附連結。
- 使用者可以選擇讓 AI 認識自己：規劃的答案、持股、自己說過的事。這些只留在使用者的裝置，伺服器不保存。
- 小圈子階段用邀請碼擋住陌生人，並限制每人用量，避免成本失控。
- 之後能調整：提示版本化、有一組固定的範例問題可以人工檢驗回答品質。

## 非目標

- 帳號系統、跨裝置同步、伺服器端保存對話或記憶。
- 連接外部儲存（關聯式資料庫、SaaS、向量資料庫、NoSQL）。本系統不含這些；記憶透過請求帶入，日後要接外部來源時，只需要換「誰組出這份記憶」。
- 下單、連券商、任何會改變使用者資金的動作。工具一律唯讀。
- 推播通知（維持後續階段）。

## 反目標

- 把 AI 編出來的數字當成事實呈現。預測可以錯，但引用的數字與新聞必須真的存在。
- 把使用者的持股金額或個人資料送進搜尋引擎或第三方工具。
- 讓網頁內容（不可信）指揮 AI 做事。
- 把 AI 的觀點包裝成保證或「一定會」。

## 使用者已決定的事

- AI 可以做預測，依據公司近況與新聞、公司之間的關係、歷史規律與紀錄，像專業分析師一樣給出具體答案。（使用者已決定）
- 問「要不要調整」時，給事實、描述選項，並且給出建議。（使用者已決定）
- AI 要記得使用者到某個程度，可以提供持股等狀況以得到更精準的建議；外部儲存不在本系統內。（使用者已決定）
- 可以提供 skills、MCP、搜尋引擎給 AI 使用，讓它能查更多。（使用者已決定）
- 階段切分：4A 問問看後端 → 4B 聊天畫面 → 4C PWA 收尾。（使用者已決定）
- 每日解讀與規劃說明維持「只講事實、不預測」，不受這次改變影響；只有問問看是「AI 的聲音」。（沿用既有決定）

## 我的決定

**兩種文字，兩套規則。** 現有驗證器（禁預測、禁建議用語）只用在每日解讀與規劃說明。問問看使用自己的提示與檢查，不共用。

**回答的結構（提示規定，UI 依此呈現）：** 結論（一兩句）→ 依據（事實與來源，網路來源附連結）→ 情境（上漲、持平、下跌各一，各說什麼訊號會出現）→ 對你的意義（有提供資料才有）→ 建議（具體，說清楚是 AI 的觀點）→ 信心程度（低／中／高，加一句為什麼）。入門視角用白話並附名詞晶片；專業視角用原名詞並可給更多數據。每則回答下方固定一句：「這是 AI 的觀點，不是保證，也不構成投資建議。」

**入口：** `POST /api/ask` 串流（AI SDK `streamText`，OpenAI 相容 endpoint）。請求帶：對話紀錄、視角、選填的 `profile`（規劃答案、持股清單、使用者要 AI 記住的事）。伺服器不保存對話與 profile，日誌只記次數與 token，不記內容與金額。

**存取控制：** 邀請碼（既有 `INVITE_CODES`）換簽章 cookie（新增 `AUTH_SECRET` 環境變數，Zod 驗證）。每個邀請碼身分每天訊息數與每則工具呼叫步數有上限；用量計在資料庫（只記雜湊後的身分、日期、次數、token，不記內容）。上限數字放設定，預設保守。

**內建工具（唯讀，從 DB 讀，不打上游）：** 今日市場與溫度、族群排行與明細、詞彙表、指定標的歷史價格與報酬、使用者規劃的確定性結果（由請求中的規劃答案呼叫既有 `planService` 算出，AI 不自己算）、最新每日與每週解讀。

**外部工具：** 環境變數 `ASK_MCP_SERVERS`（JSON 陣列：名稱、網址、標頭用的環境變數名稱）列出要連的 MCP 伺服器，並有允許使用的工具名稱清單。搜尋引擎也透過 MCP 接入，由使用者自選與提供金鑰；本系統不綁定特定服務。工具結果一律標示為不可信內容，AI 只能引用不能服從；單次對話工具步數與每個工具的逾時有上限。

**隱私保護：** 提示告知 AI 持股金額與數量是私人資訊。伺服器在送出任何外部工具呼叫之前，檢查參數是否含有 profile 裡的金額數字，含有就拒絕該呼叫並回報給模型。持股代號可以用在搜尋（查新聞需要），這點會在畫面上寫明。

**事實查核：** 回答串流完成後，伺服器比對文字中的數字與工具結果、系統資料；對不上的數字在畫面上標「這個數字沒有對應到資料來源」，不擋下回答。

**端點不支援工具呼叫時：** 降級為只使用內建資料與 context 回答，畫面註明「這次沒有查網路」。第一步先實測使用者的 endpoint 是否支援工具與串流。

**記憶（裝置端）：** 對話紀錄與 profile 存瀏覽器本機。AI 可以建議「要不要記住：你兩年內想買房」，使用者按同意才寫入「記住的事」，可以在設定頁檢視、編輯、清除。持股由使用者自己輸入（代號、選填金額）。清除按鈕一次刪除全部。

**聲音開關：** `ASK_VOICE=analyst | facts_only`。預設 `analyst`（小圈子階段）；`facts_only` 使用只講事實、不預測不建議的提示，作為公開前法規審視後的備案。

**品質檢驗：** 一份版本化的範例問題集（含使用者的四個例子，約 20 題，入門與專業各半），每題附檢查項目（結論先行、有來源、有情境與信心、不編數字、不洩漏私人資料）。使用者的 endpoint 就緒後由人工跑一輪並閱讀回答；測試用假模型與假工具，不連真實 LLM。

**畫面（4B）：** 路由 `/ask`，導覽加「問問看」，手機底部導覽變五項（需要在實作時確認寬度，必要時把設定留在齒輪）。空白時顯示四個建議問題；輸入框固定在底部；回答串流顯示，名詞變成名詞晶片，來源連結新分頁開啟；工具使用中顯示「正在查 xxx」；對話與記憶的清除放在畫面與設定頁。離線時說明需要連線。

**PWA 收尾（4C）：** 安裝提示（`beforeinstallprompt` 與 iOS 說明）、更新提示（有新版時提示重新載入）、檢查 manifest 與圖示、離線頁面對問問看說明需要連線、邀請碼輸入畫面。

**Skills 的意思（我的詮釋，請確認）：** 放在 repo 的 `src/ask/skills/*.md` 的「分析手冊」，例如「如何拆解一個族群的行情」「如何用入門視角解釋名詞」「如何評估一檔 ETF」。模型有一個 `loadSkill(name)` 工具，需要時才載入對應手冊；系統提示只列出手冊的名稱與一行說明。MCP 伺服器自己提供的工具照一般工具處理。這樣日後加新的分析方法只需要新增一個檔案。

**邀請碼範圍：** 只保護 `POST /api/ask`（會花 LLM 費用的唯一新入口）。登入端點 `POST /api/auth/invite` 與簽章 cookie 在 4A；邀請碼輸入畫面隨 4B 一起做（聊天畫面需要它），4C 不再包含。既有唯讀 API 維持開放；`/api/plan` 的用量限制仍在公開前清單。每個邀請碼視為一個人，每天（台北時間）訊息數有上限；token 只記錄不設限。

**對話與請求大小：** 伺服器強制：最多 20 則訊息、請求主體 64 KB 以內（含每回合重送的 profile），超過就拒絕並回報；客戶端也會在送出前裁掉最舊的訊息。

**事實查核的範圍：** 「有依據」的數字＝本回合工具結果＋系統資料＋使用者 profile 與使用者自己說過的數字＋先前回合已出現過的數字。工具結果不會回傳給客戶端重送，所以每回合只針對本回合重新查核。AI 自己做簡單算術得出的數字（加總、百分比變化）若能由有依據的數字推得，不標記。這是盡力而為的軟性提示，標記延遲在串流結束後以額外的串流資料段送達，畫面容許少量誤報。

**隱私檢查的保證程度：** 盡力而為的防護，不是保證。伺服器在送出外部工具呼叫前，檢查參數是否含有 profile 與「記住的事」裡的金額與數量（含常見寫法：純數字、千分位、萬／億）；持股代號與西元年份不算。「記住的事」與 profile 會給模型看，但模型被告知不得寫進外部查詢。畫面會寫明：持股代號可能出現在搜尋裡，金額不會（盡力防止）。

**端點能力：** 以環境變數 `ASK_TOOLS=on|off` 靜態決定是否使用工具（預設 on，第一步實測後設定）；請求中工具呼叫失敗時，該次改用無工具回答並註明。必須支援串流；不支援串流時一次回傳完整回答。`POST /api/ask` 不由服務工作者快取（既有規則：`/api/*` 一律 NetworkOnly，4A 加測試確認）。

## 公開前的新增門檻

問問看的預測與建議（`analyst` 聲音）列入公開前法規審視；必要時以 `ASK_VOICE=facts_only` 上線。LLM 成本與用量上限、帳號系統維持原本的公開前清單。
