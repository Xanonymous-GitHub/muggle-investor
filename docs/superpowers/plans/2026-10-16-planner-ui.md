# Planner UI (Phase 3B) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the `/plan` screen: a questionnaire (one question per page on phones, one page on desktop), then a result with level, reserve, allocation, rhythm, the stored LLM explanation, a historical comparison chart and the assumptions, for both lenses and both themes.

**Architecture:** Client components under `src/ui/plan/`, mirroring `src/ui/today` and `src/ui/sectors`: pure view-model functions, small presentational cards, one screen component holding a form ⇄ result state machine. Answers live in `localStorage` only; the plan comes from `POST /api/plan` (never cached), the explanation from `GET /api/plan/explanation` through the existing `useResource`. Charts use shadcn `chart` (Recharts).

**Tech Stack:** vinext/React 19, TypeScript, Tailwind v4 + shadcn (radix-nova), Recharts via `shadcn add chart`, Vitest (`dom` project, happy-dom), existing UI hooks.

**Spec:** `docs/superpowers/specs/2026-10-16-muggle-investor-planner-ui-design.md` (binding; draft mockups at https://claude.ai/artifact/E8PbfSDo7FssJLuADUvRQV). Also `docs/superpowers/specs/2026-10-14-muggle-investor-planner-design.md` and the UI conventions in `docs/superpowers/specs/2026-10-13-muggle-investor-ui-design.md`.

## Global Constraints

- Bun, TypeScript, Biome, Zod 4; every dependency at its latest version (`bun run deps:check` reports nothing). New dependency: `recharts` (through the shadcn `chart` component), latest.
- Tests first (RED/GREEN evidence), signed commits, no pushing from tasks. No live LLM or live data source anywhere; component and hook tests use fakes.
- `src/ui/**` imports server modules with `import type` only; never import `@/db`, `@/server`, or the `@/glossary` barrel (it pulls Zod schemas) — use `@/glossary/terms` like `term-chip.tsx`.
- Red is up, green is down (`text-up` / `text-down`, `trendClass`); every signed number carries its sign; colour is never the only signal.
- Money in the API is whole TWD; ratios (`xirr`, `cagr`, `maxDrawdown`, `volatility`, `worstYear`) are fractions (0.1792 = 17.92%); `xirr`, `cagr`, `worstYear` can be `null`.
- Fixed sentences on screen, never from the LLM: 「過去表現不代表未來。」 and 「以上為資料整理與教育說明，不構成投資建議。」 (the second is `DISCLAIMER` in `src/ui/today/view-model.ts`; reuse it).
- Never show the level while the user is answering; never put two levels' returns side by side; every history view prints its own window (`from`–`to`, years).
- All user-facing strings of the planner live in `src/ui/plan/copy.ts` with a header comment marking them as drafts awaiting the user's review (same convention as `src/ui/sectors/copy.ts`).
- Mobile first: no horizontal page scroll at 360 px; targets ≥ 44 px; visible focus states; respects `prefers-reduced-motion`.
- Gate before each commit: `bun run lint && bun run typecheck && bun run test`; before the last commit of a task that changes routes or the build also `bun run build`; the last task also `bun run deps:check`.

## Review Focus

- Amount input edge cases: empty, `12.5`, `1,000,000,001`, `-5`, full-width digits, leading zeros, pasted `600,000`, both lump and monthly zero.
- A slow `POST /api/plan` response must never overwrite the result of newer answers (race), and an unmount must abort the request.
- Corrupt or old `muggle.plan.draft.v1` content (wrong types, unknown option ids, extra keys, invalid JSON, storage that throws) never breaks the screen.
- `xirr`/`worstYear` null, a window under a year (`insufficient_history`), `reserve_only`, bond held as cash (`warnings`), `cappedByHorizon`, `equityOnly: null` (no toggle shown), level 1 and level 5 specifics.
- The 「只有股票」 toggle never mixes its window with the main run's numbers (table, metrics and chart all switch together; the window label is always the one on screen).
- Lens switch (Settings) while a result is on screen changes labels only, never refetches the plan.
- Offline and failed fetch keep the saved answers and offer a retry.

### Task 2: Draft model, amount parsing and copy
