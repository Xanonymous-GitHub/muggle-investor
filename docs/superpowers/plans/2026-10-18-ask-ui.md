# 問問看畫面（Phase 4B）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The `/ask` screen: invite-code gate, streaming chat against `POST /api/ask`, safe answer rendering with notices / number marks / remember card / term chips, and an on-device "my data" panel (plan opt-in, holdings, memory notes, clear all).

**Architecture:** Client components under `src/ui/ask/`. Pure modules first (limits, device stores, request builder, answer parsing), then one chat hook that reads the UI message stream, then the screens. Everything the user types or saves stays in `localStorage`; the server stores nothing. No new backend behaviour.

**Tech Stack:** React 19 (vinext App Router), TypeScript, Tailwind v4 + shadcn (sheet, button, input, badge), AI SDK 7 client side (`@ai-sdk/react` and/or `ai` readers — verify against node_modules), a safe Markdown renderer (`react-markdown` without raw HTML, or a small in-house parser), Vitest 5 (`dom` project, happy-dom).

**Spec:** `docs/superpowers/specs/2026-10-18-muggle-investor-ask-ui-design.md` (binding), on top of `docs/superpowers/specs/2026-10-17-muggle-investor-ask-design.md`. Wire types: `src/ask/ask-message.ts`. Server contract: README "Ask backend" section.

## Global Constraints

- All dependencies latest (`bun run deps:check` lists nothing outside cooldown); new dependencies (`@ai-sdk/react`, `react-markdown` if used) at latest.
- Tests first (RED/GREEN), signed commits ending with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`, no push from tasks, no subagents; fakes only (fake fetch / fake streams); no live LLM, no network. Never print or commit `.env` values.
- `src/ui/**` imports server modules with `import type` only; never `@/db`, `@/server`, `@/ask/*` values, the `@/glossary` barrel (use `@/glossary/terms`). Shared limits are duplicated in `src/ui/ask/limits.ts` with a test comparing them to `src/ask/schema.ts`.
- Everything user-facing is Traditional Chinese, all strings in `src/ui/ask/copy.ts` (draft wording header like `src/ui/plan/copy.ts`).
- Red up / green down where numbers appear; colour never the only signal; targets >= 44 px; focus visible; `prefers-reduced-motion` respected; no horizontal scroll at 360 px.
- Privacy: nothing leaves the device unless the user sent a question; `profile.plan` only when the opt-in is on and the draft is complete; holdings and memory only what the panel shows; no `console` output of messages; no message text in URLs.
- localStorage keys: `muggle.ask.chat.v1`, `muggle.ask.holdings.v1`, `muggle.ask.memory.v1`, `muggle.ask.profile.v1`, `muggle.ask.ack.v1`; all reads tolerant per field (bad value → dropped, never throws); writes never break the UI.
- Request limits (copy of the server's): 20 messages, 4000 chars per message, 30 holdings, 20 memory notes, 200 chars per note, body <= 60 KB UTF-8 bytes (server cap is 65,536).
- Gate: `bun run lint && bun run typecheck && bun run test` per task; `bun run build` for route/build changes; last task adds `deps:check`.

## Review Focus

- Markdown/XSS: raw HTML in an answer never renders; `javascript:`, `data:` and protocol-relative links never become links; links open in a new tab with `rel="noopener noreferrer"`.
- IME: pressing Enter to confirm a Chinese composition (`isComposing`, `keyCode 229`) never sends; Shift+Enter inserts a newline; double tap on send sends once.
- Stream handling: abort (stop button, unmount, new chat) leaves no state update after unmount and no dangling fetch; a 401 mid-session returns to the invite screen; a stream error keeps the text received so far; a second send while streaming is ignored.
- Memory is written only by the user's click on 記住 (never by the stream); the remember line is parsed strictly (last line only, exact prefix with the full-width colon, plain text) and never shown twice.
- Privacy surface: what the "我的資料" panel says will be sent equals what `buildAskBody` actually sends (test against the same inputs); opt-in defaults to off; clearing removes every `muggle.ask.*` key.
- Corrupt or oversized localStorage (non-JSON, wrong shapes, 5 MB strings) never crashes the screen.

### Task 4: The chat hook

**Files:**
- Modify: `package.json`/`bun.lock` (`@ai-sdk/react` at latest only if used)
- Create: `src/ui/ask/use-ask-chat.ts`, `src/ui/ask/use-ask-chat.test.tsx`, `src/ui/ask/stream-fixture.ts` (test helper building a UI-message-stream response body from chunks)

**Interfaces:**
- Consumes: `buildAskBody`, stores (Task 2), `AskNotice`/`AskVerification` types (`@/ask/ask-message`, type-only), `useSettings` lens.
- Produces: `useAskChat(options?: { fetchImpl?: typeof fetch }): AskChat` with
  `AskChat = { turns: Turn[]; status: "idle" | "streaming"; error: AskError | null; send(text: string): void; stop(): void; newChat(): void; signedOut: boolean }`
  where `Turn = { id: string; role: "user" | "assistant"; text: string; notices: AskNotice[]; verification: AskVerification | null; tools: { name: string; done: boolean }[]; streaming: boolean; failed: boolean }`
  and `AskError = { kind: "rate_limited"; used: number | null; limit: number | null } | { kind: "unavailable" } | { kind: "too_large" } | { kind: "signed_out" } | { kind: "offline" } | { kind: "failed" }`.
  Behaviour: `send` ignores empty/whitespace text, text over 4000 chars (returns without sending), and any call while `status === "streaming"` (double-send guard); appends the user turn and an empty streaming assistant turn; POSTs `buildAskBody(...)` to `/api/ask` (`cache: "no-store"`, `AbortController`); maps 401 → `signedOut: true` + error `signed_out` (no assistant turn left behind), 413 → `too_large`, 429 → `rate_limited` with the `x-ask-used`/`x-ask-limit` headers, 503 → `unavailable`, network error → `offline` when `navigator.onLine === false` else `failed`; on 2xx reads the UI message stream: text deltas append to the assistant turn, tool-input parts add `tools` entries and tool outputs mark them done, `data-notice` and `data-verification` parts fill the turn, an `error` chunk sets `failed` on the turn but keeps the text; the finished turns (text only) are persisted with `writeChat` after each completed answer (not during streaming); `stop()` aborts, keeps partial text, marks the turn not-streaming; `newChat()` aborts, clears the list and the stored chat; unmount aborts and never sets state afterwards; on mount the stored chat is restored (after hydration, not during render).

- [ ] **Step 1: Failing tests (fake fetch with `stream-fixture`)** — happy path text across 3 deltas; tools + notice + verification parts; error chunk mid-stream keeps text and marks failed; 401 / 413 / 429 (headers) / 503 / network / offline mapping; double send ignored while streaming; over-length text not sent; abort via `stop()` keeps text; unmount mid-stream triggers no state-update warning and aborts the fetch; restored chat on mount; persistence only after completion; `newChat()` clears the store; the body sent equals `buildAskBody` for the same inputs (assert the JSON); a `Retry` after an error resends without duplicating the user turn (decide and test the behaviour: the failed assistant turn is replaced).
- [ ] **Step 2: Run, see them fail.** Run: `bunx vitest run src/ui/ask/use-ask-chat.test.tsx`.
- [ ] **Step 3: Implement.** Parse the stream with the AI SDK helper that turns an SSE response into UI message chunks (verify the exact export in `node_modules/ai`; if there is none for the client, parse `data: <json>` lines yourself with `parseJsonEventStream`/`uiMessageChunkSchema` equivalents) — `useChat` is optional; the contract above is what the screens depend on.
- [ ] **Step 4: Pass; lint/typecheck/test. Commit:** `feat(ask-ui): chat hook with streaming, abort and error mapping`.
