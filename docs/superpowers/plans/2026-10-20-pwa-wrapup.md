# PWA wrap-up (Phase 4C) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Muggle Investor a well-behaved installed app: an install prompt (Chromium `beforeinstallprompt` and an iOS Safari how-to), an update prompt when a new version has been installed, a correct manifest and icons, and offline wording that says what works and what needs a connection.

**Architecture:** Two small client hooks (`useInstallPrompt`, `useUpdateAvailable`) feed one dismissible notice area in the app shell and one row in Settings. The service worker (`src/sw.ts`, `skipWaiting` + `clientsClaim`) is not changed in behaviour; the page learns about a new worker through `controllerchange`. The manifest gets a real maskable icon, an `id`, and shortcuts.

**Tech Stack:** vinext, React 19, TypeScript, Serwist (existing), Vitest (node + happy-dom), Tailwind v4, shadcn.

**Spec:** this document's "Design" section is the spec; it extends `docs/superpowers/specs/2026-10-17-muggle-investor-ask-design.md` ("PWA 收尾（4C）") and `docs/superpowers/specs/2026-10-11-muggle-investor-design.md` ("PWA"). Items marked (my decision) can be vetoed by the user.

## Design

**What exists:** `public/manifest.webmanifest` (name, standalone, icons 192/512 where the "maskable" entry reuses the plain 512 icon, whose artwork is not inside the maskable safe zone), `src/sw.ts` (precache + NetworkFirst pages + NetworkOnly `/api/*`, shell routes cached at install, `skipWaiting`, `clientsClaim`), `src/components/service-worker-registration.tsx` (registers only in production), the offline banner in `app-shell.tsx`, and (4B) the offline composer line and read-only offline open of `/ask`.

**Install prompt (my decision):**
- `useInstallPrompt()` returns `{ mode, install }`. `mode` is `"installed"` (standalone display mode or `navigator.standalone`), `"prompt"` (a `beforeinstallprompt` event was captured and `preventDefault()`ed), `"ios"` (iOS Safari, not standalone, no event: show how-to text), or `"none"`. `install()` calls `prompt()` on the saved event and resolves to `"accepted" | "dismissed" | "unavailable"`; the saved event is discarded after one use. `appinstalled` sets `"installed"`.
- A dismissible notice in the shell (below the mobile header, above the offline line): 「把 Muggle Investor 加到主畫面，開啟更快、像一般 App。」 with 「安裝」 (mode prompt) or 「點分享按鈕，再選『加入主畫面』」 (mode ios), and 「先不要」. Dismissal is stored as a timestamp in `muggle.pwa.install-dismissed.v1` and hides the notice for 30 days. Never shown in `installed` or `none` mode.
- Settings gets a row 「安裝到主畫面」 shown in `prompt` and `ios` modes, regardless of dismissal (same action), and 「已安裝」 text in `installed` mode.

**Update prompt (my decision):**
- `useUpdateAvailable()` returns `{ ready, reload }`. `ready` becomes true when `navigator.serviceWorker` fires `controllerchange` AND the page already had a controller when it loaded (so the first-ever install does not prompt). `reload()` calls `location.reload()`.
- The page also asks the registration to check for an update (`registration.update()`) when the tab becomes visible again, at most once per hour.
- A notice 「有新版本可以使用」 with 「重新載入」; no automatic reload (a streaming answer or an unsent draft must not be lost). Not dismissible except by reloading; it is a `role="status"` line, not a modal.
- `src/sw.ts` keeps `skipWaiting: true` and `clientsClaim: true` (unchanged, per the existing offline design).
- The registration component exposes the registration to the hook through a tiny module-level store (no new dependency).

**Manifest and icons (my decision):** add `"id": "/"`; keep the `any` icons; add a real `maskable` icon `public/icons/icon-maskable-512.png` (same dark background and green bars, artwork scaled into the central 80% safe zone, full-bleed background) and point the maskable entry at it; add `shortcuts` for 今日 (`/`), 問問看 (`/ask`) and 規劃 (`/plan`) using the 192 icon; keep `theme_color` `#ffffff` (the layout's `viewport.themeColor` already switches by colour scheme). The icon is generated by a committed one-off script `scripts/make-maskable-icon.ts` or rendered with the pre-installed Chromium; no new runtime dependency. A unit test parses the manifest and checks: required fields, every icon and shortcut icon exists on disk with the declared size, a maskable icon exists and is distinct from the `any` 512 icon, `start_url` and `scope` are inside the app, every shortcut `url` is in `APP_SHELL_ROUTES`.

**Offline wording (my decision):** on `/ask` the shell's offline line reads 「目前離線。問問看需要連線才能提問，你可以先看之前的對話。」; other routes keep 「目前離線，顯示的是上次載入的資料。」 (4B already disables the composer with 「需要連線才能提問」 and shows the saved chat on an offline cold open).

**Reduced motion (my decision):** the shared Sheet overlay and content slide/fade animations (`src/components/ui/sheet.tsx`) get `motion-reduce:` overrides so no animation runs when the user asks for reduced motion (a 4B review carry-over).

## Global Constraints

- `src/ui/**` imports only `import type` from server code; no `@/db`, `@/server`, `@/ask` values, no `@/glossary` barrel.
- No new runtime dependency; versions stay as `bun run deps:check` accepts (it must stay clean).
- All strings are Traditional Chinese, collected in one `copy.ts` per feature (draft wording, flagged for the user's review).
- Touch targets ≥ 44 px (except inline term chips, R-B7); `role="status"` for passive notices, `role="alert"` only for errors; focus-visible rings.
- Storage keys are namespaced `muggle.pwa.*`; every read/write is try/catch and tolerant.
- The service worker only registers in production; hooks must be inert (and testable) when `navigator.serviceWorker` is missing.
- Signed commits, TDD, full gate `bun run lint && bun run typecheck && bun run test && bun run build && bun run deps:check`.

## Review Focus

1. `beforeinstallprompt` fires before the hook mounts or never fires: the hook must cope (listen at module load, replay to late mounters) and must not leak or double-prompt.
2. A new worker takes over while the user is mid-answer or has a draft: no automatic reload; the notice stays until the user reloads.
3. First visit (no controller yet) must not show the update notice; a reload after update must clear it.
4. iOS detection must not show the how-to on desktop Safari or inside the installed app; iPadOS reports as Mac (`navigator.maxTouchPoints`).
5. Dismissed install notice stays hidden for 30 days, survives reload, and a corrupt stored value shows the notice again instead of throwing.
